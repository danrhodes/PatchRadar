    Announcements and messages

    This section provides key notifications related to this release, including announcements, change logs, and end-of-support notices.

    Important

    Windows 11, version 24H2 Home and Pro has reached end of updates. The October 2026 monthly security update is the last update available for these editions. Devices running these editions will no longer receive monthly security and non-security preview updates containing protections from the latest security threats. To stay protected and up to date, we recommend you upgrade to the latest version of Windows 11.

    Windows Secure Boot certificate expiration

    Secure Boot certificate updates remain in progress as Microsoft transitions devices from certificates that began expiring in 2026 to newer certificates. Devices that have not yet received the newer certificates can continue to start and receive standard Windows updates. Microsoft will continue delivering the newer Secure Boot certificates to eligible devices through Windows Update.

    Improvements

    This update includes improvements from the following previously released updates:

    • September 8, 2026-KB5124008 (OS Builds 26200.9445 and 26100.9445)
    • September 14, 2026—KB5129195 (OS Builds 26200.9457 and 26100.9457) Out-of-band
    • September 22, 2026—KB5124010 (OS Builds 26300.9550, 26200.9550, and 26100.9550)

    The following summary outlines key quality improvements addressed by this update. The bold text within the brackets indicates the item or area of the change.

    • [Security updates] This update provides security improvements. For more information about the security vulnerabilities resolved by this update, see the Security Update Guide.

    • [Secure Boot] This update continues the deployment of updated Secure Boot certificates using the latest high-confidence targeting data to identify eligible devices that are ready to automatically receive the new certificates. Deployment through Windows Update remains ongoing across supported devices.

    • [Windows Explorer (Known issue)] Fixed This update fixes an issue that affects Windows Explorer in multi-user environments, such as Azure Virtual Desktop and FSLogix. After sign-in, Explorer.exe might fail to start or repeatedly crash, causing a black screen.

    • [Audio (known issue)] Fixed This update fixes an issue that affects AC-3 audio playback in some applications.

    • [Always On VPN] This update fixes an issue that affects Always On VPN connections after installing KB5124008. When automatic protocol selection or protocol fallback was configured, affected VPN connections could remain stuck in a Connecting state or fail to connect after an initial connection attempt failed. In some cases, subsequent connection attempts could display the error, "The specified port is already in use."

    • [Storage Spaces] This update fixes an issue that affects tiered Storage Spaces Direct virtual disks. Some virtual disks might fail to come online after installing certain security updates, making dependent clustered workloads unavailable.

    • [Date and Time] This update introduces the new (UTC-05:00) Manitoba time zone to support Manitoba’s November 1, 2026, time zone change.

    • [ReFS security] This update adds auditing and optional policy controls for ReFS volumes on externally attached storage devices. Auditing is enabled by default, while enforcement controls remain disabled by default to give administrators time to evaluate and prepare for future security hardening changes. To learn more, see KB5130741.

    • [Printing] This update resolves an issue where printing could fail in some applications and on devices using RAW or Generic Text Only printer drivers after installing the August 2026 security update.

    • [Gaming] This update fixes an issue that could cause mouse input to stutter in some games.

    • [Windows Hello] This update fixes an issue where fingerprint sign-in might not work after a cold boot on some devices.

    • [Authentication] This update strengthens NTLMv1 security by changing the internal default behavior when the BlockNtlmv1SSO registry value is not set. Windows now uses Enforce mode (1) instead of Audit mode (0), blocking the generation of NTLMv1-derived credentials for Single Sign-On (SSO). This change applies only to devices where Credential Guard is disabled and the BlockNtlmv1SSO registry value is not set, and might affect Wi-Fi, Ethernet, and VPN connections that use MS-CHAPv2-based authentication. For more information, see KB5066470.

    If you've already installed previous updates, your device will download and install only the new updates included in this package.

    Known issues in this update

    You might be unable to turn on Smart App Control

    Symptoms

    After installing this update, some devices might be unable to turn on Smart App Control in the Windows Security app if it has been turned off. On affected devices, the option to turn on Smart App Control might be grayed out.

    Devices where Smart App Control is already turned on are not affected and remain protected.

    Resolution

    Important: This section contains information about modifying the registry. Before you modify the registry, back it up and make sure that you know how to restore it if a problem occurs. For more information, see How to back up and restore the registry in Windows.

    Option #1: Modify the registry

    You can modify the registry to restore the ability to turn on Smart App Control by following these steps:

    1. Open a Command Prompt window by typing cmd in the Search box.

    2. Select Run as administrator.

    3. At the command prompt, enter the following commands. Then restart the device.

      reg add "HKLM\SYSTEM\CurrentControlSet\Policies\Microsoft\FeatureManagement\Overrides" /v 2883193997 /t REG_DWORD /d 1 /f

      reg add "HKLM\SYSTEM\CurrentControlSet\Policies\Microsoft\FeatureManagement\Overrides" /v 2850574478 /t REG_DWORD /d 1 /f

    Option #2: Install a Group Policy

    IT administrators can instead choose to mitigate this issue for enterprise-managed devices managed by IT departments by installing and configuring the special Group Policies listed below.

    Group Policy downloads with Group Policy name:

    • Download #1 for Windows 11, versions 24H2, 25H2, and 26H2 — KB5074105 261015_19222 Feature Preview
    • Download #2 for Windows 11, versions 24H2, 25H2, and 26H2 — KB5074105 261015_19221 Feature Preview

    Important: You should install and configure both Group Policies to resolve this issue. The first Group Policy is needed to turn on Smart App Control. The second Group Policy ensures that logging is available to assist with troubleshooting in case any problems arise.

    The special Group Policies can be found in Computer Configuration > Administrative Templates > {Group Policy name} > Windows 11, version 24H2, 25H2. After installing the Group Policies, configure the value for both settings to Enabled and restart your device(s) to apply the Group Policy settings.

    Next steps: Microsoft is working on a resolution and will provide an update in an upcoming release.

    Remote Desktop connections might fail for non-admin users with error 0xC000000D

    Symptoms

    After installing the September 2026 non-security preview update KB5124010, or later updates, non-admin users might be unable to establish Remote Desktop connections to remote devices that have Administrator protection enabled. Attempts to connect might fail with error 0xC000000D and display the message, “The token that was passed to the function is invalid.” This issue primarily affects enterprise-managed remote devices used as Remote Desktop hosts with Administrator protection enabled, regardless of how the feature was enabled.

    Note: If your organization uses Windows security baselines, published through the Microsoft Security Compliance Toolkit, Administrator protection is enabled by default in Windows 11, version 24H2, 25H2, and 26H2 security baselines, unless your organization has configured the policy differently.

    Resolution

    IT administrators can mitigate this issue on devices affected by the Remote Desktop connection failure by using their existing policy management method to temporarily turn off Administrator protection. Reset the User Account Control Type Of Admin Approval Mode policy in Microsoft Intune or Group Policy. For more information, see Administrator protection on Windows 11.

    Next steps: Microsoft is working to address this issue in a future Windows update and will provide more information when it is available.

    USB audio devices might fail to start or produce no sound

    Symptoms

    After installing the September 8, 2026, Windows security update (KB5124012), some USB Audio Class 1.0 devices might fail to start or produce audio. Affected devices might experience one or more of the following symptoms:

    • The device displays an error in Device Manager: "This device cannot start (Code 10).”

    • No audio output.

    • Volume controls are unresponsive or remain at zero.

    • Sound settings are unresponsive or unavailable.

    Some devices might function in standard stereo configurations but fail when using multichannel audio features, including 8-channel or 3D audio modes. Some customers have reported that they're able to restore audio in these cases by switching to 2-channel mode.

    This issue is limited to USB Audio Class 1.0 devices.

    Resolution

    This issue is partially resolved in the out-of-band (OOB) update released on September 14, 2026, (KB5129195). This OOB update resolves the symptoms experienced on devices using 8-channel or 3D audio modes. Microsoft is working to address the other symptoms and will provide more information when it is available.

    IT administrators who need an immediate workaround for the symptoms not addressed yet by the OOB update should contact Microsoft Support for Business for assistance.

    How to get this update

    Deployment

    If you deploy dynamic updates such as this update to an existing Windows image, ensure the boot.stl file is included as part of the installation media. Failure to include the file might prevent devices from successfully starting from the installation media and can result in error code 0xc0430001.

    Note

    The boot.stl file is used during Secure Boot validation and must match the Windows version and architecture of the image you are updating.

    To ensure the boot.stl file is included as part of the installation media, do one of the following:

    • Use the Update WinPE script to update an existing Windows image. (Recommended)
    • Manually copy the boot.stl file from the device Windows\Boot\EFI folder to the corresponding folder on your installation media before deploying the update.

    For information about how to apply Dynamic Update packages to existing Windows images, see Update Windows installation media with Dynamic Update.
